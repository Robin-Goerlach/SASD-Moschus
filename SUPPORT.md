# Support

## 1. Project phase

SASD Moschus is currently in its foundation phase. No format is production-
ready merely because it appears in the planning documents.

## 2. Where to ask

- Use a GitHub issue for reproducible bugs, documentation defects and focused
  feature proposals.
- Use a GitHub discussion, when enabled, for research questions and broad
  design conversation.
- Use the private process in [SECURITY.md](SECURITY.md) for vulnerabilities.

Before reporting, check `docs/format-coverage.md` and the exact format
specification. A family name or extension alone may not identify the file.

## 3. Information for a useful bug report

- Moschus version or commit;
- operating system and compiler/build;
- command or public API call;
- exact options and resource limits;
- detected and expected format version;
- expected and actual result;
- full diagnostic codes, with sensitive paths redacted;
- minimal redistributable file or a hash/private-offer note;
- provenance and permission to inspect the sample.

Do not upload personal, confidential, copyrighted or proprietary data without
permission.

## 4. Compatibility questions

Ask about an exact version/profile, for example `GIF89a` or a named dBASE DBF
variant. “Does Moschus support .doc?” is too broad because the extension covers
different file formats and versions.

## 5. No guaranteed service level

The open-source project provides no guaranteed response or repair time. Paid or
contractual support is not implied by the repository. Critical security issues
are prioritised according to the security policy.
